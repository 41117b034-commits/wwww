## 進入與操作

完成第五批接應後會自動進入第六批，沒有新的場景入口或第六批快捷鍵。

| 操作 | 作用 |
| --- | --- |
| 空白鍵 | 在可略過的字幕中略過當句，仍保留最短閱讀時間；不跳過達多行走、後倒、清點流程，也不直接結束兩輪交談。輸入文字／中文組字時保留給輸入。 |
| Enter／「送出」 | 章末聊天送出一則有效文字。空白、只有符號、中文組字中的確認鍵或等待回覆時重複送出，不計新一輪。 |
| 「聽莫那說話」 | 完成兩輪有效輸入及巴萬回覆後出現。聊天紀錄保留供閱讀，玩家點此按鈕才繼續；第二輪回覆不會自動切走。 |
| 「重試保存」 | 完整結尾後若保存失敗，結束卡顯示此按鈕；成功後才恢復「重玩第三章」。 |
| 「重玩第三章」 | 結束卡沿用第三章重玩入口。已保存結果保留，直到下一次完整結尾成功保存時取代。 |

結尾演出與聊天期間不提供戰鬥或自由行走；劇情依段落安排觀看方向。桌面留下分支以淡出切到林路、再恢復接應處視角。

## 生還、死亡與清點

- **救援比胡：** 第五批扶行到接應處、達多接手後，比胡維持原受傷坐姿休息，仍能回應同伴；巴萬與達多確認他生還。救援操作失敗仍按第五批檢查點規則重試，不改成死亡結果。
- **留下比胡：** 比胡留在原受傷點。達多先說明要回去找他，沿既有林路實際走回；到身旁後，比胡以原骨架從受傷倒坐姿勢慢慢向後倒下，胸口朝上、四肢放鬆伸展至仰躺終點，約 2.8 秒後保持靜止，沒有血腥效果。骨骼旋轉混合後，骨盆中心依倒坐與仰躺的起終點，以相同平滑權重沿直線下降、平移，避免中段因骨架旋轉而抬高；頭、胸、髖分別靠近地面，另保留軀幹防穿地與局部手腳接地處理。達多再沿林路實際返回接應處，回報比胡死亡。巴萬只親眼見過受傷與留下，死亡由達多回報，沒有被寫成目擊死亡瞬間。

清點固定包含原小隊的玩家、巴萬、比胡、達多：救援為四人生還，留下為玩家、巴萬、達多三人生還。莫那不是這四人的原小隊成員，也沒有參與學校與受傷現場；他稍後抵達接應處聽取回報，不加入四人／三人的清點數字。

分工回顧對應學校實際隊伍：選巴萬線是玩家與巴萬在左、達多與比胡在右；選比胡線是玩家與比胡在右、達多與巴萬在左。清點同時確認玩家仍攜帶所選的單一獵刀或村田十八年式步槍。

兩輪交談後，莫那從接應處外走近，先聽巴萬回報分工與比胡結果，再說分支收尾與共同撤入山林的台詞。莫那沿用駐在所既有角色；離開本段時還原其原父物件、位置、朝向及啟用狀態。

## 章末交談

交談對象固定為巴萬，保留玩家原文與回覆的可捲動紀錄，共兩輪。關於生死、人數、人物、分工與武器的問題使用符合目前結果的固定答覆；自由想法與情緒才交給既有對話服務回應。固定狀態問題先辨識明確詢問的角色：巴萬與達多仍生還、沒有受傷，比胡依救援／留下結果回答；「巴萬，你知道比胡死了嗎」中的稱呼不會讓問題被誤當成詢問巴萬的生死。巴萬對另一條學校路線只知道匯合後的轉述；留下分支的死亡資訊來自達多回報。

聊天階段莫那尚未到達接應處，因此談到他的知情狀態時，只說稍後向他回報；不能把完成存檔中「已聽取回報」的資料提前用於聊天。只有玩家按「聽莫那說話」後，才進入他到場與聽取回報的段落。

`Outcome` 開始時會先呼叫 `PrepareService()`，沿用既有 `Chapter2LocalDialogue` 服務的 `Prepare()`，讓載入與結果演出、清點重疊；正式等待回覆的計時仍從送出問題後開始。

請求預設等待上限為 15 秒。逾時、服務錯誤、空白或涉及改寫受保護劇情事實的生成文字，改用符合分支的預寫回應，介面會標示已接續預寫回應。模型回答不改生死、任務、武器、章節進度或存檔；第二輪不再反問，也不代替莫那收尾。F8／跨區取消時會取消請求，過期回覆不接回新流程。

真實服務紀錄曾連續取得兩次生成回覆，耗時分別為 10.99 秒、11.87 秒；但先前冷啟動測試兩輪都在約 15 秒逾時後接續預寫回應，第二輪也沒有成功生成。這些是個別觀察，預先準備服務與一次成功紀錄均不能保證每次請求的速度或成功率。

## 保存時機與第四章讀取介面

`Chapter3Ending.Begin` 先用 `Chapter3ResultStore.Build` 建立 `completed=false` 的本次結果快照。只有兩輪交談、莫那聽取回報與收尾台詞、最後淡出全部完成後，`Chapter3Ending` 才呼叫 `SaveCompleted`；成功後再以 `Load` 讀回確認，結束卡顯示結果已保存。受傷選項、清點、聊天回答、檢查點重試及 F8 都不會提前提交本次結果。

儲存使用 `PlayerPrefs` 的 `WusheEvent.Chapter3.Result` 字串鍵，內容為版本 1 的 JSON。有效完成結果會取代同鍵的上一筆完成結果；重玩或跳段本身不刪除舊結果。`PersistResult=false` 供驗證時隔離存檔，不代表正式遊戲已保存。

| `Record` 欄位 | 意義 |
| --- | --- |
| `version` | 目前固定為 `1`。 |
| `completed` | `Build` 時為 `false`，保存的副本為 `true`。 |
| `mission` | `Chapter3SchoolBattle.Mission.Bawan` 或 `.Pihu`。 |
| `decision` | `Chapter3Rescue.Decision.Rescue` 或 `.Leave`。 |
| `weapon` | `Chapter3Weapons.Weapon.Knife` 或 `.Rifle`，保留單一武器。 |
| `pihuSurvived` | 由救援／留下選擇固定決定的生還值。 |
| `squadSurvivors` | 包含玩家、排除莫那的原小隊生還人數：`4` 或 `3`。 |
| `actors` | 固定依巴萬、比胡、達多、莫那順序的四筆角色知情資料；這是角色資料陣列，不是生還名單，也沒有玩家的獨立角色項目。 |

每筆 `ActorKnowledge` 包含 `actorId`（`bawan/pihu/tado/mona`）、`schoolSide`（`west/east/none`）、`originalSquad`、`alive`，以及 `westSchool`、`eastSchool`、`injury`、`outcome` 四種知情來源。來源列舉為 `None`、`Direct`、`Reported`：各人自己走的學校路線為親歷，另一側為匯合後轉述；原三名同伴親歷受傷，莫那則聽取接應回報。留下分支中，達多親眼確認死亡、巴萬聽轉述，比胡不取得死後後續資訊。莫那的 `Reported` 是結尾報告完成後的紀錄，不可拿來讓他在回報前預知事件。

第四章可使用：

```csharp
Chapter3ResultStore.Record result = Chapter3ResultStore.Load();
if (result != null)
{
    bool pihuAlive = result.pihuSurvived;
    int survivors = result.squadSurvivors;
    string bawanKnowledge = Chapter3ResultStore.KnowledgeSummary(result, "bawan");
}
```

`Load()` 只回傳完整、合法且 `completed=true` 的版本 1 紀錄；沒有結果、JSON 損壞、欄位缺漏／多出／型別錯誤、重複欄位、未知版本或與固定分支事實不符時，回傳 `null`。`IsValid(record, requireCompleted)` 可檢查紀錄，`KnowledgeSummary(record, actorId)` 只整理固定遊戲事實。保存內容不包含玩家自由輸入、LLM 提示詞或聊天紀錄。

本輪只提供第四章承接資料與讀取 API，沒有建立正式第四章場景、流程或新章節入口。第七批整章整合與驗證仍未製作。

## 程式與驗證狀態

- `Chapter3Ending`：結果演出、達多往返、清點、借用／還原莫那、結束卡及最後保存。
- `Chapter3EndingConversation`：兩輪交談、固定事實回答、生成與備援、明確按鈕交接及取消。
- `Chapter3ResultStore`：固定結果格式、知情範圍、嚴格讀取與完成保存。
- `Chapter3InjuryPose`：`DeathWeight`／`SetDying(0..1)` 控制從倒坐慢慢後倒至放鬆仰躺，骨盆沿起終點直線插值；`ResetPose` 清除死亡與受傷姿勢。沿用現有骨骼，沒有複製或烘焙全身高面數網格。
- `Chapter3Rescue`：接應完成後交接第六批，跨區時清理第六批與姿勢。

姿勢的獨立檢查以 `SetDying(0／0.25／0.5／0.75／1)` 逐段渲染診斷與正式鏡頭；到終點時記錄骨架全部 Transform 的世界位置與旋轉，兩秒後比較，位置差須小於 0.001 公尺、旋轉差小於 0.1 度，並另查說話狀態已關閉、`ResetPose()` 清除受傷／扶行／死亡三層。這能檢查靜止與重設，但不能取代半程接地、仰躺自然度或完整結尾流程的視覺驗收。
