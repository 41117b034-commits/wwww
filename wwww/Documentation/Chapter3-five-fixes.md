# 第三章五張截圖修正

日期：2026-10-20～21。使用者授權直接修改截圖 1–5；學校襲擊史實只討論，沒有因此重寫學校任務或分工。

## 本輪行為

1. 領取武器後，準備出發對話立即顯示，但回答欄先等 E／右手拿取按鍵放開，再排除拿取事件留下的輸入。等待期間暫停 InputField，避免它上一輪排入的延後 focus 重開 IME。解鎖前只清空一次，解鎖後保留玩家正常輸入的 e／注音；取消時恢復原 InputField 與 legacy IME 模式。
2. 巴萬說「莫那，我們到了」後，莫那加入歡迎與互相照應的台詞，再接原駐在所說明和單一武器選擇。新增內容是遊戲創作，並非史料引文：
   「你來了。歡迎你加入我們，一起反抗日本警察的壓迫。這條路不好走，記住，要和同伴彼此照應。」
3. 山路右側跟隊者為比胡。原來追上移動目標就停步並轉看玩家，下一幀又轉回行走；改為追蹤連續移動的位置，只在真正停等時面向玩家，兩同伴啟用既有步態過渡。PathMotor 保留 Actor 已完成的落地高度修正。
4. 山路與學校共用警察命中規則：頭、軀幹和手臂一槍；大腿、小腿與腳兩槍。警察使用十二個貼合原骨架的命中區，取代不保證對準可見身體的固定根膠囊。第一槍腿傷剩 50 生命值、停止前進、短暫停止開火並蹲低；第二槍腿／腳死亡。受傷姿勢沿用原骨架與腳底 IK，命中區跟隨姿勢；保留原手部修正、單發裝填、掩體、同伴與群眾保護、獵刀傷害。
5. 連續入校的中央木柵同時移除可見幾何與碰撞，兩側保留。原程式只認作者工具的 `School geometry *` 名稱，正式場景已是 `Combined_*`，因此曾只關碰撞卻留下可見木柵。現在支援正式名稱，且只在確認中央每段可見幾何成功移除後才開放通行。F8 直接進校時維持原完整來路柵欄。

## 驗證與交付

本輪修改前備份、臨時驗證工具及報告：`_CodexBackups/chapter3_five_fixes_20261020/`。最終結果以該目錄的 `final-summary.json` 為準。

三份最終 Editor Play Mode 報告共 **295 項通過**，均 `completed=true`、`errors=[]`、`warnings=[]`：

- `test-input.json`：18 項。實際開場兩輪回答、莫那歡迎、步槍選擇與領取、E 按住／放開的輸入閘門、後續正常文字與取消恢復。駐在所出發後觀察比胡 35 秒，497 個移動樣本沒有行走中反轉朝向，步行／停等切換 5 次。領取前用定位 fixture 移到桌邊；E 由 Input System 驅動。沒有把這段觀察當成完整重跑至學校。
- `test-movement.json`：84 項。F8 封閉中央有 62 個可見三角形；連續入校準備後中央為 0，側面 36 個保持，碰撞分別通行／阻擋；再 F8 恢復。用巴萬與 PathMotor 定位 fixture 確認中央可走、側柵不能穿過。
- `test-combat.json`：193 項。山路與學校各測頭、軀幹、上臂／前臂、大腿、小腿與腳，以正式武器 Attack／Trace 射線命中確切骨骼區，沒有直接注入命中傷害。腿傷第一槍生命值 50、蹲姿權重超過 0.95、頭下降至少 0.25m，實際 2.6 秒裝填後第二槍死亡。另測掩體擋彈、同伴保護及原兩刀傷害。使用實際警察模板複製體、定位／停火 fixture；三種警察模板另完成必要骨骼名稱核對。

測試區分 Editor 驅動、實際武器射線、角色／攝影機定位 fixture、Windows 原生按鍵。不得將 `SetTextWithoutNotify` 的中文字串檢查當成原生注音輸入驗證；不得把停火／定位 fixture 測試當作真人完整遊玩。原生 VR 與新 Standalone 建置不在本輪驗收內。

Windows 原生驗證嘗試：自動化送出的 E／F6 沒有進入 Unity 遊戲輸入，無法實測注音組字。`native-input.json` 的 completed 只表示測試情境準備完成，**不列入上述 295 項，也不代表原生鍵盤通過**；詳見 `native-input-limit.txt`。實際 Windows 注音仍待玩家確認。

第一輪輸入測試碰上 Play 中腳本重新編譯，造成非序列化初始化資料遺失；報告封存在 `diagnostic-reload`，不列為最終通過證據。後續只在編譯、assembly reload 和 Edit Mode 檢查完成後啟動測試。最初手臂射線 fixture 未對準的報告封存在 `diagnostic-combat`，調整測試定位後完成上述 193 項；未弱化命中區判定。
