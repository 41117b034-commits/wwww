# 第一至第三章對話停頓與武器輸入診斷

2026-11-04。依使用者要求縮短語句空檔，另查明開槍／揮刀延遲；武器規則本輪未修改。

## 對話修正

- `ChineseSpeechPacing` 在第一次播放中文固定錄音或即時合成音訊時，縮短近乎靜音的區間並快取結果。10 ms 區塊峰值門檻 0.0015；開頭保留 60 ms、結尾 100 ms，句中超過 600 ms 的空白保留 320 ms。保留非靜音樣本順序、採樣率與聲道，不以提高播放 pitch 加速。原 WAV、角色聲線設定與中文台詞不改寫。
- 第一章中文顯示時長改跟隨錄音；開場旁白與警方對話完整播放後只留 120 ms 接句。族人質問的獨立計時也跟隨中文配音，行走、推擠、踢酒、鏡頭移動及原演出等待不一律壓縮。
- 第二章有錄音時採實際長度加最多 120 ms，不再取舊字幕秒數的較大值。無錄音保留原文字閱讀時間，原族語錄音綁定維持。
- 第三章共用 `WaitForLine` 等完整音訊後接句，不再讓短句等滿舊 4～8 秒設定；缺音保留原文字等待，跳句規則不變。族語錄音與原 .95 pitch 風格維持。

實測例子：第一章「我們只是辦婚禮，沒有冒犯。」原 WAV 3.43 秒，處理後 2.72 秒；第三章「去吧。」原莫那 WAV 1.87 秒，其中尾端約 1.18 秒近乎靜音，處理後 0.65 秒。四角色短句的完整等待約 0.72～1.27 秒（含 Editor 幀間隔），不再等滿傳入的 6 秒。

## 武器問題的實際證據

`Chapter3Weapons.cs` 保持原檔雜湊。本輪在正式山路戰鬥入口重現：

- 就緒時 `Attack()` 當次呼叫立刻增加揮刀／射擊次數，Input System 合成左鍵也能經正式 `Update()` 觸發。
- 刀的冷卻是 0.68 秒；冷卻中再次按下會被拒絕，沒有輸入緩衝，等冷卻完不會自動補揮。
- 刀的命中判定在揮動開始後 0.22 秒執行，是揮刀動作的一部分。
- 槍射出後有 0.48 秒復位，此期間按 R 同樣會被拒絕；空膛必須裝填。單發裝填固定 2.6 秒，實測 2.622 秒，過程中的攻擊不會排隊補發。

這些遊戲規則可以直接造成「按了沒反應」，不需要假設滑鼠或電腦故障。

另在前景 Unity Editor 獨立重進第三章取樣：正常繪製中位 126.42 ms／幀，約 7.9 FPS；32／32 幀 `Application.isFocused=true`，`WaitForTargetFPS` 0 ms。暫停全部遊戲相機繪製後為 63.20 ms／幀，約 15.8 FPS，64／64 幀保持焦點；完成後相機設定還原。此場景取樣存在明顯幀耗時，繪製有實際影響，不能把它全歸因於背景視窗節流。一般 Behaviour Update 約 1.05 ms、尋路移動約 0.34 ms，這一小段並未顯示尋路是主要負擔。尚無 GPU 完整分析或同版獨立執行檔比較，因此不能據此斷定硬體不足、GPU 故障或單一渲染瓶頸。

效能取樣使用山路起點、跳過開場、暫停三名敵人 Update 的測試設定；相機關閉只存在於 Play Mode 診斷。沒有以這個片段宣稱所有場景的 FPS。
